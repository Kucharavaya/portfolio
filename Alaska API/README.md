# API-тестирование - Alaska API

## Цель проекта

Проверить CRUD-операции REST API сервиса управления медведями Alaska API, валидацию входных данных, граничные и негативные сценарии, корректность изменений в базе данных; выявить дефекты и подготовить тестовую документацию.

## Объект тестирования

- **Тип:** REST API, CRUD-сервис для управления медведями (*bears*)
- **Docker Image:** [azshoo/alaska](https://hub.docker.com/r/azshoo/alaska)
- **Платформа:** Docker-контейнер; приложение внутри контейнера доступно по адресу `http://localhost:8080`
- **Документация API:** внутри контейнера, `GET /info`

Сервис предоставляет набор REST-эндпоинтов для создания, чтения, обновления и удаления записей о медведях. Каждый медведь описывается JSON-объектом:

```json
{
  "bear_id": 1,
  "bear_type": "BLACK",
  "bear_name": "MIKHAIL",
  "bear_age": 17.5
}
```

Допустимые значения `bear_type`: `POLAR`, `BROWN`, `BLACK`, `GUMMY`.

## Объем работ

- Анализ документации API через `GET /info`
- Определение классов эквивалентности и граничных значений для `bear_age`
- Составление чек-листа
- Разработка ~64 тест-кейсов
- Функциональное, негативное и граничное тестирование CRUD-операций
- Создание коллекции Postman
- Оформление баг-репортов
- Сводка выполненных проверок по методам и типам сценариев

## Проверенные функции

- `POST /bear` — создание медведя с валидацией всех полей (`bear_type`, `bear_name`, `bear_age`), проверка дублирования, негативные сценарии
- `GET /bear` — получение всех записей, в том числе из пустой БД
- `GET /bear/:id` — получение существующего и несуществующего медведя
- `PUT /bear/:id` — обновление всех полей и отдельных полей, негативные сценарии (`400`/`404`)
- `DELETE /bear/:id` — удаление существующего, повторное удаление, удаление несуществующего
- `DELETE /bear` — удаление всех записей и удаление при пустой БД
- `GET /info` — проверка отображения документации API

## Классы эквивалентности и граничные значения для `bear_age`

| Позитивные классы | Граничные значения |
|---|---|
| 0 – 100 | -0.01, 0, 0.01, 99.99, 100, 100.01 |

| Негативные классы | Граничные значения |
|---|---|
| от -∞ до -0.01 | для -∞ нет, -0.01 |
| 17.000000005 | 17.000000005 |
| от 100.01 до +∞ | 100.01, для +∞ нет |
| строковое значение | нельзя определить |
| спецсимволы | нельзя определить |

## Что было выполнено

В рамках тестирования Alaska API реализовано полное покрытие CRUD-операций:

| Категория | Количество тестов | Описание |
|---|---:|---|
| `POST /bear` | 46 тест-кейсов | Создание медведя с валидацией всех полей (`bear_type`, `bear_name`, `bear_age`), проверка дублирования, негативные сценарии |
| `GET /bear` | 2 тест-кейса | Получение всех записей, в том числе из пустой БД |
| `GET /bear/:id` | 2 тест-кейса | Получение существующего и несуществующего медведя |
| `PUT /bear/:id` | 8 тест-кейсов | Обновление всех полей и отдельных полей, негативные сценарии (`400`/`404`) |
| `DELETE /bear/:id` | 3 тест-кейса | Удаление существующего, повторное удаление, удаление несуществующего |
| `DELETE /bear` | 2 тест-кейса | Удаление всех записей и удаление при пустой БД |
| `GET /info` | 1 тест-кейс | Проверка отображения документации API |

**Итого:** ~64 тест-кейса, сгруппированных по методам и типам сценариев (`200`, `400`, `404`).
